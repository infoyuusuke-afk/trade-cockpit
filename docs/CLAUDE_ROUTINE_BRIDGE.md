# ChatGPT ↔ Claude Code 自動受け渡し（有効化用）

これは公開リポジトリの [共有シート](AI_SHARED_SHEET.md) を受け渡し場所にする運用手順。**このファイルの存在だけではClaudeは起動しない**。Claude側で下記Routineを1回作成・有効化して初めて、PCが停止中でも定期的に共有シートを確認できる。ChatGPT側の既存定期確認は別途設定済み。

## 一度だけ行う設定（リポジトリ管理者のClaudeアカウント）

1. [Claude Code Routines](https://claude.ai/code/routines) にサインインし、GitHubの `infoyuusuke-afk/trade-cockpit` へのアクセスをClaude側で許可する。資格情報をチャットや公開リポジトリに貼らない。
2. 新しい**定期実行**Routineを作り、対象リポジトリを `infoyuusuke-afk/trade-cockpit` に設定する。平日・日本時間の**18:30頃**を目安とする（ChatGPT側の共有シート確認は平日17時頃だが、実際の実行時刻はずれる場合がある）。最初に1回手動実行して、履歴・返信ファイルの実際の更新を検証する。
3. 次の「Routineに入力する指示」全文を指示欄に貼る。権限は可能な限り対象リポジトリに限定。許可が得られない・Routinesが提供されない場合は無効のままにし、ユーザーに状態を報告する。

### Routineに入力する指示

あなたは `infoyuusuke-afk/trade-cockpit` のClaude Code側レビュー担当です。まず公開リポジトリの最新mainを読み、`STATUS.md`、`CLAUDE.md`、`docs/AI_SHARED_SHEET.md`、`docs/CLAUDE_BRIDGE_RESPONSES.md` を確認してください。作業ツリーに他者の変更がある場合は上書きしないでください。

共有シートのChatGPT発 `C-数字` 行のうち、返信ファイルに同じIDが未記録のもの、またはChatGPTが再検証を明示的に求めた新しい証拠があるものだけを処理してください。情報源、データ取得時点、比較対象、OR15等の定義、サンプル数を確認し、各IDについて「確認済み / 要追加検証 / 反証 / 対応見送り」「根拠となるファイル・公開リンク」「次の担当・必要な実機確認」を `docs/CLAUDE_BRIDGE_RESPONSES.md` に一行ずつ記録してください。確認できなければ断定せず「要追加検証」としてください。新規IDがなければ**書き込まず終了**してください。

このRoutineは連絡と検証だけを担当します。売買注文、Windows内MS2/Excelの起動・接続、秘密情報のアップロード、実装コードの自動変更、GitHub Pagesへの自動デプロイは行わないでください。技術修正が必要なら検証結果と候補のテスト計画を返信欄に記載し、別の開発作業として扱ってください。共有シートの他者の行は編集・削除しないでください。

結果を書き込める場合は変更を返信ファイルのみに限定してGitHubへ反映し、反映後に最新mainを再取得して自分の行を確認してください。競合・認証失敗なら成功と報告せず、Routineの実行ログに失敗理由を残してください。公開リポジトリには個人情報、PCパス、保有数量、未公開のRSS板・歩み値ログ、資格情報を書かないでください。売買の最終判断は常に本人です。

## 受け渡しの判定

- ChatGPT→Claude: [共有シート](AI_SHARED_SHEET.md)に根拠・時点・ID付きでChatGPT行が実際にコミットされた状態。「送信」ではなく「受け渡し先に置いた」だけ。
- Claude→ChatGPT: [返信ファイル](CLAUDE_BRIDGE_RESPONSES.md)に元IDへの回答が実際にコミットされ、最新mainで読み直せる状態。
- この二つが成立して初めて双方向の受け渡しを確認できる。Routineの実行成功・実装完了・本番表示は別々に検証する。
- 不明な価格や統計は捏造しない。市場全体の情報を銘柄固有の約定データと混同しない。

## 制約

Routinesの利用可否・GitHub連携・実行権限はClaudeアカウントに依存する。ChatGPTからそのアカウントを操作・ログイン・作成することはできない。GitHubへの文章更新はWindowsローカルのMarketSpeed II RSSを起動せず、ライブ板情報も取得しない。急を要するザラバの判断をこの定期連携に依存しないこと。
